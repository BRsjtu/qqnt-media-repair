# 兼容性与支持的记录配置文件

## 已验证基线

目前的兼容性结论仅限于观察和验证过的以下环境：

- Windows QQ 9.9.31-49738，x64。
- Python 包 `sqlcipher3==0.6.4`，使用 CPython 3.13 Windows x64 `.pyd` 适配器，并在使用前校验预期哈希（底层为 SQLCipher 4）。

该基线不代表所有 QQ 版本、数据库布局或适配器构建都可用。请在本机运行记录中保留工具报告的版本和适配器身份。不得将初始基线宣传成广泛兼容。

## 命名的旧版文件卡片配置文件

只有同时确认以下条件，记录才符合当前范围：

- 属于旧版 `FILE` 元素，且 `type=3`、`subtype=1`。
- 旧版 ASCII 32 位 MD5 字段 `45407` 标识该文件卡片媒体。
- 字段 `45507` 存在过时失败标记 `-7003`，或字段 `45509` 存在无效标记。
- 原始文件字节在本地存在且可读取；必须从这些实际字节计算哈希。

不得假定所有失败媒体记录都使用此配置文件。不得仅因为记录较旧或媒体不可用就清除标记。不得声称所有过期媒体均可恢复。

## 明确图片路径补回配置文件

新增命名配置：`explicit-image-media-path-rehydration-v1`。已验证的代表性场景为普通图片：聊天记录中有明确的本地原图路径，原图路径缺失，但其他本机目录中仍有大小、实际 MD5 和 SHA-256 均经核验的原始字节。按记录中已有的原图及缓存路径逐字节补回后，原聊天显示与原生图片查看器中的真实图像均已验证恢复；此流程不需要修改聊天数据库或清除错误状态。

`broad_media_scan.py` 只执行清点和来源验证，不执行补回。`restore_targets` 完整保存非引用、无元数据冲突的明确缺失路径；当前只接收字段 `45403` 指向账号 `nt_qq/nt_data/{Pic,Emoji,Ptt,Video,File}/.../Ori/...` 的目标。目标来自原记录，不能根据缩略图路径猜测原图路径。同一目标出现不同已验证来源时，将其移出目标表并写入阻止及冲突表。表中的其他媒体类型属于待调查目标，不能据此扩大普通图片的 UI 验证结论。

该配置只支持有本机原始字节且路径和身份可确定的情况。正常原图仍在、仅缩略图缺失，不构成已证实损坏。索引提示、路径缺失、错误标记或“已找到候选”均不能代替实际字节验证及原聊天/查看器验证。补回应只创建不存在的目标，不覆盖既有文件，不能自动修改未知标记。图片以外的媒体、引用媒体或未知 schema 仍须单独建立验证范围。

## 其他 schema 和媒体

未知 QQ 版本、变化后的 schema、不同标记、超出上述已验证配置的媒体或缺少原始字节的记录，均不在当前修复范围内，需先调查。广域清点可以报告这些记录，但不会将其自动列为已修复或可修复。任何扩展都应使用有代表性的单聊和群聊记录验证，确认原始字节和 UI 行为，并建立单独命名的配置文件。范围外记录保持不变，并注明原因。

索引中找不到原件，并不能证明其他位置也没有副本，例如手机或备份。应将其标记为未处理，或“在此索引数据源中未找到原件”；不得推断服务器过期或永久丢失。
