# QQNT 媒体批量修复

入口为 `scripts/qqnt_repair.py`，先运行 `--help`。此 skill 面向批量修复：在 QQ 中确认 1–2 条原始文件卡片后，应继续处理已验证配置文件下的全部合格记录，不能把流程缩成逐条修复。

执行依赖为 Windows x64、Python 3.13、已核验二进制的 `sqlcipher3==0.6.4`，可使用 `uv run --python 3.13 --with sqlcipher3==0.6.4 -- python <脚本路径> ...`。命令顺序为 `scan` → `apply --sample 1`（或 2）→ 打开 QQ 实测并退出 → `confirm-ui` → `apply` 批量处理 → `status`。`rollback` 根据加密计划做有条件的行级逆向恢复。已有同机同版实测时，`confirm-ui --existing-cases` 可复用证据，避免重复抽样修改。各命令用 `--help` 查看必填参数。

操作顺序和收尾报告要求见[批量工作流](references/workflow.md)。判断记录是否符合当前支持范围前，先读[兼容性说明](references/compatibility.md)。

## 必须完成的工作

- 从已安装程序和配置中确认当前 QQ 数据根目录，并与用户当前使用的账号核对。解析 junction 和路径别名；不得仅凭磁盘上某个目录看起来合理就猜测数据根目录。
- 为获得稳定读取状态，先退出 QQ。密钥文件和数据库操作都留在本机。使用已有且获授权的本地密钥提取流程，并通过 SQLCipher 确认密钥与所选数据匹配。不得打印、上传或写入报告密钥。
- 清点支持范围内的单聊和群聊，生成 dry-run 计划，记录合格记录、跳过记录及原因、原文件路径，以及实际原始字节的哈希。
- 若此前未获授权，在修改前取得针对本次任务的授权。用户明确授权修复目标数据，即覆盖整批合格记录，无需逐条请求许可。1–2 条 UI 抽查用于确认配置文件，不替代获授权的批量处理。
- 保留加密的受影响行回滚包；临时数据库快照同时最多保留一份。密钥、报告、快照和运行产物不得放入公开示例或版本库。
- 发布前确认源锁定与 WAL 处理正确、只使用已提交状态，并通过完整性检查。不能把运行中的数据库直接当作稳定快照。
- 重新打开 QQ，确认原卡片预览与双击行为，并抽查单聊、群聊以及批次中较早和较新的代表性记录。
- 收尾时分别统计已修复且 UI 验证的记录、各原因跳过记录、失败记录和未处理媒体。不得将未处理媒体算作已修复或已丢失。

若 schema 或标记不符合所述配置文件，相关记录不得修改。先调查并验证代表性案例，再扩展为单独命名的配置文件；不得悄悄清除状态标记。安全的情况下，可继续处理现有支持配置文件的整批记录，并报告未知或范围外项目。
